# 生物多样性观测 · 分类沿革整理

把跨年观测记录按现行物种分类整理，供分布模型使用。Flask + SQLite，Docker Compose 一键启动。

## 功能与规则

- **观测 CSV**：`record_no, initial_taxon, quantity` —— 记录号文件内唯一、数量为非负整数、至多 100 行。
- **分类沿革 CSV**：`round, old_id, new_id` —— 轮次为 1~4 的整数且从 1 开始连续、至多 40 行。
- **逐轮追踪**：同一轮内允许一对多（拆分）与多对一（归并）；未列出的编号沿用到下一轮；
  每轮对当前编号集合整体映射一次（同一轮内不做链式展开，链条在后续轮次继续解析）。
- **可用 / 待核**：全部轮次结束后，所有路径落到同一编号的记录进入可用数据；
  仍有多个去向的记录列为待核并给出原因（拆分轮次、最终去向），**数量不能分摊**，保留原数量待人工核定。
- **整份更正**：两份 CSV 每次上传都替换整份并生成新修订，旧修订与其计算结果保留可查（可下载原文）。
- **结果固定输入修订**：每次计算记录所固定的观测修订与沿革修订。
  - 任一输入更正后，旧的当前结果立即失效（仍可在“计算记录”中查询）；
  - 计算完成时若固定的修订已非最新（迟到计算），结果仅留作历史，不作为当前结果；
  - 运行与全部结果在同一事务写入，**失败不开放半份结果**，只留一条无结果的失败记录。
- **整库备份与恢复**：网页一键下载整库备份、上传备份并经确认页显式确认后整库替换恢复。
  - 备份涵盖全部输入修订（编号、原文、SHA-256）、全部计算记录（成功/失败、当前标记、固定修订）
    与全部结果行（可用/待核），恢复后编号、输入文本与 `is_current` 当前结果标记原样保留；
  - 仅接受本应用导出的完整备份：ZIP 内含魔数标识、逐表 SHA-256 与基于 `SECRET_KEY` 的 HMAC-SHA256
    签名；损坏、缺件、篡改、签名不符或引用缺失一律在写库前拒绝，原库不变；
  - 恢复在单事务内完成（按外键顺序清表 → 按原 id 写回 → 同步自增序列 → 递增库版本号），
    失败或中断整体回滚，只可能保留恢复前或恢复后的完整状态；恢复成功后可继续更正与计算；
  - **并发安全**：每请求以快照事务读取，恢复与读取交错时只能读到完整旧库或完整备份；
    库版本号（generation）构成写围栏，恢复前已开始的上传、计算及其失败记录在恢复成功后
    一律回滚、不得写回，即使两边修订号相同。
- 列名支持常见中英文别名（记录号/初始分类号/数量、轮次/旧号/新号等），编码支持 UTF-8（含 BOM）/ GBK。

## 启动（Docker Compose）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

SQLite 数据保存在命名卷 `app_data`（容器内 `/data/app.db`）。生产部署请覆盖密钥：

```bash
SECRET_KEY=$(openssl rand -hex 32) docker compose up -d --build
```

## 本地开发

python3 -m venv .venv && . .venv/bin/activate

## 页面

- **首页**：当前输入修订、重新计算（默认固定最新修订，可改选旧修订）、当前结果（可用记录 + 待核原因）。
- **上传观测 CSV / 上传沿革 CSV**：整份更正，校验失败逐行提示且不保存。
- **计算记录**：全部运行（成功/失败、是否当前、固定的修订、可用/待核数）。
- **输入修订**：两份输入的全部修订，含 SHA-256 与原文下载。
- **备份与恢复**：下载整库备份 ZIP；上传备份先完整校验并预览，再确认替换恢复（可取消）。

## 备份与恢复操作流程

```bash
# 1. 浏览器打开「备份与恢复」→ 下载整库备份（backup_<时间戳>.zip）
# 2. 需要恢复时：上传该 ZIP → 查看内容预览 → 点「确认替换并恢复」
#    - 校验不过（损坏 / 非本应用导出 / 引用缺失）会直接拒绝，库不变
#    - 确认后整库回到备份时状态；恢复后新修订号接续备份中的最大编号
```

注意：备份 HMAC 签名依赖 `SECRET_KEY`，请在部署时固定并妥善保管该环境变量；
更换 `SECRET_KEY` 后，此前导出的备份将无法通过签名校验。待确认的备份暂存在
容器内 `/data/restore_staging`（确认或取消后立即删除，不落业务库）。

## 说明与取舍

- 观测记录按“每条记录”追踪，不在记录之间合并数量；多对一只影响分类号归属。
- 应用未加登录鉴权，面向内网/单机使用；如需多人协作请自行前置认证。
- 上传上限 1 MiB（行数限制已远小于此）。
